# CodeAgent OJ 前端页面设计

## 1. 设计目标

产品的主界面是高密度、低干扰的算法工作台。用户的主路径是“选题 → 写代码 → 运行/提交 → 查看结果 → 获得恰当帮助 → 复盘”，页面必须让代码编辑和判题结果保持第一优先级。

视觉建议采用白色和浅灰的内容底色、深色代码区、蓝色作为主要操作色、绿色/红色仅用于通过/失败反馈。卡片圆角不超过 8px，避免大面积装饰性渐变。使用 Lucide 图标，并为仅图标按钮提供悬浮提示。

## 2. 全局框架

桌面端采用固定顶栏、可收起左导航和主内容区：

```text
┌───────────────────────────────────────────────────────────────────────┐
│ Logo   题库  学习中心                         搜索   通知   头像       │
├───────────┬───────────────────────────────────────────────────────────┤
│ 主页      │                                                           │
│ 题库      │                    当前页面内容                           │
│ 学习中心  │                                                           │
│ 错题本    │                                                           │
│ 管理      │                                                           │
└───────────┴───────────────────────────────────────────────────────────┘
```

- 顶栏高度 56px；左导航宽 216px，可收起为 56px 图标栏。
- 内容区最大宽度不限制题目工作台，其他列表/学习页最大 1440px 并居中。
- 全局搜索支持题号、标题和标签；`/` 聚焦搜索。
- 桌面优先适配 1280px 以上；平板折叠左导航；手机改为底部导航，题面、编辑器和 Agent 面板使用全屏切换。

## 3. 页面清单

| 页面 | 路由 | 主任务 |
| --- | --- | --- |
| 首页 | `/` | 继续训练、查看今日计划与最近提交 |
| 题库 | `/problems` | 搜索、筛选、比较和选择题目 |
| 题目工作台 | `/problems/:slug` | 阅读、编码、运行、提交、请求多 Agent 帮助 |
| 提交详情 | `/submissions/:id` | 查看完整判题结果与 Agent 诊断 |
| 学习中心 | `/learning` | 查看知识点、错题和训练计划 |
| 错题本 | `/mistakes` | 重做、归因和归档错题 |
| 个人设置 | `/settings` | 语言、主题、Agent 辅导强度与隐私设置 |
| 管理端 | `/admin/problems` | 题目、测试点、版本和审核管理 |

## 4. 首页

首页不使用 Hero。首屏从上到下依次为：

1. **继续做题**：显示最近一道未完成题，题目难度、标签、上次提交状态与“继续”按钮。
2. **今日训练**：3 到 5 道按优先级排序的题目列表，右侧显示计划完成进度。
3. **近期动态**：最近提交、通过率、连续练习天数和最新 Agent 建议。

首页的推荐理由只在题目二级信息中展示，例如“二分边界错误后推荐”，不打断用户快速进入编辑器。

## 5. 题库页

```text
┌─────────────┬─────────────────────────────────────────────────────────┐
│ 筛选        │ 题库                                  排序  视图切换     │
│ 难度        ├─────────────────────────────────────────────────────────┤
│ 标签        │ 状态  编号  标题             难度   标签      通过率     │
│ 状态        │ 已完成  1     Two Sum         Easy   Array     62%       │
│ 公司/题单   │ 尝试过  15    3Sum            Medium Array     41%       │
│             │ 未开始  42    Trapping Rain   Hard   Stack     28%       │
└─────────────┴─────────────────────────────────────────────────────────┘
```

- 左侧筛选栏使用多选复选框与数量计数；窄屏时变为筛选抽屉。
- 列表支持状态、难度、标题、标签、通过率和收藏；每行点击进入题目，收藏使用图标按钮。
- 表格首列以颜色点+文字表达状态，不能只依赖颜色。
- 加载时保留表格行高度的骨架屏；无结果提供“清除筛选”命令。

## 6. 题目工作台（核心）

默认采用三栏，用户可拖动分隔线调整宽度，所有列都有最小宽度，防止编辑器与结果区挤压。

```text
┌──────────── 32% ────────────┬──────────── 45% ────────────┬──── 23% ────┐
│ 题号 标题  难度  收藏       │ Python v  文件  重置         │ Agent 协作    │
│ 题目 | 提交 | 题解(解锁)   ├───────────────────────────────┤ ┌──────────┐ │
│                              │                               │ │ 路由状态 │ │
│ 题意、约束、示例、提示       │        Monaco Editor          │ └──────────┘ │
│                              │                               │ 对话与建议    │
├──────────────────────────────┼───────────────────────────────┼─────────────┤
│ 运行结果 / 提交历史          │ 测试输入 | 输出 | 判题日志    │ 辅助入口      │
└──────────────────────────────┴───────────────────────────────┴─────────────┘
```

### 左栏：题面

- 顶部固定显示题号、标题、难度、标签和收藏按钮。
- Tab 为“题目”“提交”“题解”；未满足条件时题解 Tab 显示锁定图标和可见原因。
- 示例支持复制输入和“载入编辑器下方测试区”图标按钮。
- 约束、函数签名和复杂度要求使用单独信息区块，方便扫描。

### 中栏：代码与判题

- 编辑器工具栏：语言选择、文件选择、格式化、重置模板；运行和提交为清晰文本命令按钮。
- 底部结果抽屉分为“测试用例”“运行输出”“提交历史”，保留最后一次状态，允许用户拖高。
- 提交进行中显示队列位置、当前阶段和取消按钮；取消仅终止未开始的任务。
- 判题结束使用 verdict 图标、时间、内存和失败摘要。隐藏测试仅显示脱敏摘要，例如“第 8 组边界数据未通过”。

### 右栏：多 Agent 协作面板

- 顶部显示协作状态，例如“Debugger + Reviewer 正在分析”，并显示可折叠的执行轨迹，不暴露内部推理文本。
- 快捷操作以图标+短文本排列：解释题意、给一个提示、分析代码、检查复杂度、制定计划。
- 提示分级由用户主动点击 `提示 1`、`提示 2`、`提示 3`。升级前展示将要提供的信息范围。
- Agent 返回的代码问题以可点击 `文件:行号` 跳转 Monaco；建议必须标注来源 Agent 和置信度区间。
- Safety 拦截时用简洁状态说明，并保留继续做题、换一种提问的入口。

### 工作台状态

| 状态 | 页面反馈 |
| --- | --- |
| 未登录 | 可浏览题面，运行/提交/Agent 请求引导登录 |
| 本地运行中 | 锁定重复运行按钮，不锁定编辑器 |
| 判题排队 | 显示队列状态，允许继续编辑新版本 |
| 编译错误 | 输出定位、跳转行号、调用 Debugger 快捷入口 |
| 部分通过 | 显示得分与脱敏失败类别，提供边界检查入口 |
| 全部通过 | 显示用时/内存对比、下一题与复盘入口 |
| Agent 异常 | 不影响运行/提交；展示可重试和基于规则的降级建议 |

## 7. 提交详情页

提交详情是可分享、可追溯的只读页面。顶部是 verdict 与运行指标，中部左侧为带版本标识的代码，右侧为测试摘要、编译输出和 Agent 分析时间线。用户只能访问自己的提交，管理员可按权限查看脱敏审计信息。

## 8. 学习中心与错题本

学习中心首屏使用三块紧凑信息区：本周目标/完成度、待巩固知识点、下一组推荐。下方是提交趋势和标签掌握度矩阵；使用文字和数值补充颜色。

错题本按“最近失败”“同类错误”“待复习”切换。每条包含题目、最后失败时间、错误类型、最后 Agent 建议和“重做”按钮，避免在列表中直接展示完整题解。

## 9. 管理端

- 题目列表：草稿、审核中、已发布、已下线状态，支持按作者、标签、更新时间筛选。
- 题目编辑：基本信息、Markdown 题面、语言模板、公开样例、隐藏测试、判题配置五个 Tab。
- 发布前检查：题面完整性、样例可执行性、测试点覆盖、资源限制和版本差异。
- Agent 审计：按用户、题目、Agent、策略结果和时间过滤，仅管理员访问。

## 10. 组件与响应式规范

- 使用 shadcn/ui 或基于 Radix 的内部组件库，配合 Tailwind CSS；图标统一为 Lucide。
- 基础间距采用 4px 网格；正文 14px，表格 13px，题目标题 20px，工作台内部不使用大号展示字体。
- 桌面断点：`>=1280px` 三栏；`768px-1279px` 双栏，Agent 改为右侧抽屉；`<768px` 单栏，以题面/代码/结果/Agent 底部导航切换。
- 所有异步区域提供 loading、empty、error、retry 状态；按钮有禁用、处理中和成功/失败后的明确反馈。
- 键盘体验：`Ctrl/Cmd + Enter` 提交，`Ctrl/Cmd + Shift + Enter` 运行，焦点不被流式 Agent 消息抢占。

## 11. 首期设计交付物

1. 浅色与深色主题 Token、按钮/输入/表格/状态标签等基础组件。
2. 桌面和移动端的题库、题目工作台、提交详情高保真稿。
3. 多 Agent 面板的路由中、并行分析、Safety 拦截和失败降级状态稿。
4. 前端状态机与接口映射，保证提交事件和 Agent 流式消息可独立恢复。
